# Switchyard

[English](README.md) | [日本語](README.ja.md)

クリエイティブ素材を、**検証 → 型付きのプロバイダーレビュー → 人の承認 → チェックサム付きローカル納品**の順に処理する、オリジナルのレビューアプリです。React・TypeScript・Node.jsで実装しています。

素材と応答はすべてオリジナルの架空データです。有料API、認証情報、顧客データ、外部への納品は不要です。

## 3つのコマンドで起動

Node.js 22系の22.17以降、または24以降を使用します。このディレクトリで実行してください。

```sh
npm ci --ignore-scripts
npm run build
npm start
```

**http://127.0.0.1:4310** を開きます。サーバーはこのMac内からのみ接続できるループバックに限定して起動します。実行状態と納品データは、Git管理対象外の `.data/` に保存されます。同じデータディレクトリを使うサーバープロセスは1つに限定してください。

開発時は、別々のターミナルで `npm run server -- --dev` と `npm run dev` を起動します。Viteの画面はポート5173で開きます。初回インストールでは公開npmパッケージを取得しますが、セットアップ後のデモとテストはAIプロバイダーに通信しません。

## 90秒で試せるデモ

1. **New review → Fallback recovery → Run review** を選択します。Atlasがローカルの25 ms期限を超え、Cedarが検証済みのテスト応答を返します。レビュー指摘から対応する素材を確認できます。
2. **Approve & build bundle** を押します。サーバーが承認を保存してから、6つのローカルファイルを作成します。それらの内容とハッシュを含む、検証済みのJSON納品データをダウンロードできます。
3. **Load input version 2** を押します。モーションの長さが6秒から8秒に変わります。サーバーが古い承認を取り消し、新しい入力を承認するまで納品をブロックします。
4. **Recoverable outage** で新しいレビューを作成し、`unavailable` を確認してから **Retry review** を押します。この復旧動作は、あらかじめ定めたテストシナリオです。

タイムアウト、不正な応答形式、明示的な拒否も選択できます。拒否の場合は別のプロバイダーへの切り替えを停止し、再試行による回避はできません。[日本語の技術解説](docs/walkthrough.ja.md)に、処理の流れと設計判断をまとめています。[設計とトレードオフ](docs/architecture.md)と[データ契約](docs/contract.md)は英語です。

## 動作を検証する

```sh
npm run check          # 型チェック、Lint、単体・結合テスト37件、ビルド
npx playwright install chromium  # UIテスト用の公式ブラウザーを必要に応じて導入
npm run test:e2e       # ビルド済みアプリで5つのブラウザー操作を検証
npm run demo          # 実際に実行した9件の記録を .data/demo-cases.jsonl に出力
```

アプリを起動するだけなら、テスト用ブラウザーのインストールは不要です。このMacでは `CHROMIUM_EXECUTABLE_PATH` で既存のキャッシュ済みChromiumを指定して検証しました。CIの設定では、Playwrightに対応するブラウザーをCI実行環境に導入します。2026年10月9日、Ubuntu上のNode 22.17.0・24で[GitHub Actions](https://github.com/domizo/switchyard/actions/runs/37888537230)が成功しました。各バージョンで単体・結合テスト37件とブラウザー操作5件が通り、スキーマの差分検査も成功しています。[検証記録](docs/verification.md)では、ローカルとリモートCIの結果を区別しています。

独立したFieldcheckのチェックアウトで、新しい実行記録を検査する場合：

```sh
npm run demo -- ../fieldcheck/fixtures/baseline.jsonl
cd ../fieldcheck
python3 fixtures/make_negative_controls.py
python3 -m fieldcheck fixtures/baseline.jsonl
```

## 実装済み・疑似動作・未実装の範囲

**実装済み：** スキーマ検証と素材への参照チェック、上限付きのプロバイダー切り替えと期限による中断、コマンドとチェックポイントの保存、更新バージョンによる競合検出、サーバー側での承認無効化、実ファイルのローカル納品、SHA-256チェックサム、実データを検証してからのダウンロード、プロセス再起動後の復旧テスト、キーボード操作に配慮したレスポンシブUI、CI設定ファイル。

**疑似動作：** AtlasとCedarのAIプロバイダー、応答、障害、明示的な再試行後の復旧です。決められたテスト用データ（フィクスチャ）を使います。表示する時間はローカルコードの実行時間であり、実モデルの推論速度や品質の測定ではありません。

**未実装または未検証：** 実際のAIプロバイダーとの接続、複数ユーザーの認証、クラウド実行、GCP・iOS連携、分散ワーカー、停電時の永続性、すべての支援技術でのアクセシビリティ、負荷試験、本番運用です。範囲を限定したデモであり、本番環境にそのまま導入できると主張するものではありません。
